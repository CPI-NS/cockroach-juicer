# Experiment workflow

Before planning, running or analyzing experiments, read [bench/README.md](bench/README.md) and its capability references. Use `python -m crdb_bench` for the supported SQL YCSBT scope; keep ordinary runs configuration-only, with explicit inventory, workload and pinned artifacts. Keep source, fixtures, configurations and manuals in the checkout; store run outputs under the configured `output_root` and `run_id`; maintain adapter fixes in `bench/` and reusable runtime fixes in the experiment-common repository.

For installation or a fresh checkout, read [pinned package installation](bench/packaging/README.md). Verify the common artifact against `bench/packaging/common-pin.json` and `bench/uv.lock`; use the selected environment's interpreter. Standalone execution requires experiment-common and this adapter, with no juicer-project checkout dependency. For AWS, read the installed `share/experiment-common/docs/infra.md`, or `docs/infra.md` in your experiment-common checkout. Use `python -m experiment_common.infra`: all AWS provisioning, queries, release and audit belong to the initiating host. EC2 control performs build/deploy/run/collection through SSH only, without AWS credentials or an instance profile.

Establish continuous progress observation and verify worker deadline guards before load. Use public status/stop/collection operations; verify worker → control → durable results before normal release. Worker release cleans only owned processes/workers and mechanically retains control. Separately follow [control finalization](.agents/skills/run-experiments/references/aws.md#control-finalization): record ownership, action and compute/retained-storage cost before the task; after all authorized reuse, both verified collections and no active job needs it, terminate new task-owned exclusive control with owned EBS/ENI audit, or stop explicitly reused existing control when authorized, verify stopped state and report retained billable EBS. Protect unrelated/shared control. Report unsupported capabilities explicitly before execution.

Use the maintained `run-experiments` Skill, distributed from experiment-common, for experiment execution. Its references resolve templates and documentation from the selected installed environment, not a sibling checkout. Keep the Skill version with the run handoff. Archived runner source is a reference; execute experiments through the maintained entry.
